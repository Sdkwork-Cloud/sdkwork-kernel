## 现状(已核查)

**已完备的基础设施**:
- kernel SPI(`installation.rs`):`AgentInstaller` trait 9 个操作(detect/plan/install/upgrade/uninstall/health/configuration_spec)+ 完整请求/计划/报告结构
- `installation_ext.rs`:`AgentRollbackRequest/Report`、`AgentVerifyRequest/Report`、`AgentInstallRecord` 等结构 — **已导出但零引用(死代码)**
- plugin-core `ProcessAdapterInstaller`:通用 npm/pypi 完整生命周期(检测、跨进程锁、快照、补偿回滚、幂等、超时、fail-closed)
- 6 个目标 provider(claude-code/codex/gemini-cli/opencode/openclaw/hermes)+mimo-code:安装描述符、配置 provider、包 manifest、kernel plugin 注册(installer+configuration)均已接线,但仅有描述符级测试

**差距**:
1. 升级 `rollback_required` 只加计划步骤,从不产出 `rollback_token`,也没有回滚执行路径
2. verify/rollback/list_installed 无 trait 接线,生命周期不完整
3. L3 crates 无安装生命周期契约测试(只有描述符断言);fake executor 不可复用
4. `real_process_adapter_lifecycle.rs` 漂移:codex 包 `@openai/codex-sdk`(应为 `@openai/codex`)、opencode `1.18.10`(应为 `1.18.11`)、claude-code 缺 3 个依赖
5. 规范未覆盖扩展面

## 实施计划

### 1. kernel:新增 `AgentInstallerExt` 扩展 trait(`installation_ext.rs`)
- `verify_installation(&AgentVerifyRequest) -> AgentVerifyReport`:默认由 `detect_installation` 派生(Installed→Valid、Degraded→issues、NotInstalled→NotFound),遵守 `verify_checksum` 标志
- `rollback(AgentRollbackRequest) -> AgentRollbackReport`:默认 fail-closed(`provider_error` 不支持回滚)
- `list_installed() -> Vec<AgentInstallRecord>`:默认 fail-closed(不支持盘点)
- `impl<T: AgentInstaller + ?Sized> AgentInstallerExt for T` 覆盖 `dyn` 对象;lib.rs 导出
- 契约测试:复用 `FakeAgentInstaller` 验证默认行为

### 2. plugin-core:`ProcessAdapterInstaller` 回滚 + 盘点实现
- `upgrade()` 在 `rollback_required` 时产出**不透明** rollback token(base64url JSON 快照,仅含包名/版本,绝不入事件——现有 `to_event` 已省略该字段)
- 实现 `AgentInstallerExt`:
  - `rollback`:token 必填;快照包集合必须与描述符完全一致(防注入任意包);`preserve_data=false` fail-closed(同 uninstall 边界);mutation lock 内 `restore_dependency_snapshot` + 验证
  - `list_installed`:由 detect 派生(安装→1 条记录,未安装→空)
  - `verify_installation`:沿用默认(内部已具 `verify_installed_unlocked` 语义)
- 契约测试:token 产出、回滚恢复、缺失/损坏 token 拒绝、包集合不匹配拒绝、list_installed

### 3. plugin-core:`test-utils` feature(供 L3 复用)
- `test_utils` 模块:`ScriptedProcessAdapterCommandExecutor`(脚本化输出+命令记录)、npm/pip 检测 payload 构造器、临时 install root 辅助
- L3 crates 在 `[dev-dependencies]` 声明 `features = ["test-utils"]`

### 4. 每 provider 新增 `tests/installation_lifecycle_contracts.rs`(7 个 crate)
按统一模板覆盖:检测 missing/installed/degraded → plan(步骤+policy)→ 各 dry-run 不产生命令 → 脚本化 install/upgrade/rollback/uninstall 全流程 → verify_installation → list_installed,并断言 provider 特有命令(hermes pip `--only-binary`、openclaw 无 `--ignore-scripts`、claude-code 4 包精确规格等)

### 5. 修复 `real_process_adapter_lifecycle.rs` 漂移
codex 包 id、opencode 版本、claude-code 依赖表对齐真实描述符

### 6. 规范更新
`specs/AGENT_INSTALLATION_CONFIGURATION_SPEC.md` §3 补充扩展面(verify/rollback/list_installed 规则)+ checklist

### 7. 验证
- `cargo test`(kernel、plugin-core、7 个 provider crates)
- `node scripts/check-kernel-standards.mjs`、`cargo fmt`

## 边界与说明
- **不加 HTTP 面**:安装编排/持久化归 sdkwork-agents(app-api 面),kernel 保持 SPI+实现
- `AgentInstallerExt` 为**增量**公共契约(默认方法,非破坏性),按 AGENTS.md 属需人工评审项,在实现中标注
- mimo-code 一并覆盖(仓库内结构一致,保持体系一致)
