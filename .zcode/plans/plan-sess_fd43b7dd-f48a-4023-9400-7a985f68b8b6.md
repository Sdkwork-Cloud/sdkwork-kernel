# 模型配置管理生命周期:配置体系抽象与跨仓库完整落地

## 一、现状与差距(已全面核查)

**已有资产**:
- **sdkwork-models 客户端 sqlite**(`birdcoder-user-config.sqlite3`,`SqliteUserModelConfigStore`):`user_model_channel`/`user_model_channel_model`/`user_model_key`/`user_model_engine_config`/`user_model_engine_selection` 五表,字段与 kernel 请求**1:1 对应**(base_url/default_model_id/supported_model_ids/supported_provider_ids/input/output_context_tokens/tool_call_rounds/supports_multimodal/api_key_configured/applied_at)
- **kernel 契约**(`sdkwork-agent-kernel/src/configuration.rs`):`AgentConfigurationProvider`(apply/selection/materialize×2/dematerialize/plan_upgrade/spec/validate)、`AgentConfigurationStore`(save/load/list/find/migrate/archive/subscribe/乐观锁)、profile 状态机(Draft→Active→Deprecated→Archived)、settings 分层投影
- **materializer 基础设施**(`sdkwork-kernel-plugins/.../provider_config_file.rs`):备份 `.sdkwork.bak`(已有备份绝不覆盖)+ 原子写 + 写后读回校验 + 失败回滚 + dematerialize 恢复;8 个 provider 各自写 CLI 原生配置(codex config.toml、claude/mimo settings.json、gemini .env、hermes config.yaml+.env、openclaw openclaw.json、opencode opencode.json、rig 无)

**关键差距**:
1. **持久化缺失**:profile 只存 `InMemoryAgentConfigurationStore`,重启即失;agents 无 model_configuration 表
2. **读取缺失**:HTTP 只有 apply×2 端点,无 GET/list/status;无 provider 原生配置 read-back(仅 codex 有幂等检查);无 materialize 生效状态记录
3. **生命周期死代码**:`dematerialize_model_configuration`/`archive_profile`/`migrate_profile`/`plan_configuration_upgrade` 全部未接线
4. **两端脱节**:sdkwork-models 客户端 sqlite 与 agents apply 无同步;变更订阅无消费者

## 二、抽象设计:四层配置体系 + 完整生命周期

```
L0 配置事实源    sdkwork-models 客户端 sqlite(user_model_*)
                    │ 用户编辑/变更 → HTTP 推送
L1 契约层(SPI)   sdkwork-agent-kernel:AgentConfigurationProvider + AgentConfigurationStore
                    │ AgentModelConfigurationRequest / Profile
L2 应用服务层    sdkwork-agents:SqliteAgentConfigurationStore + HTTP 面 + SecretProvider
                    │ provider apply → materialize
L3 下发目标      8 个 provider 的 CLI 原生配置(备份+原子写+读回)
```

**生命周期闭环**:编辑(客户端 sqlite)→ apply(幂等,已有)→ profile 构建+validate → materialize(写 CLI 原生配置)→ save(乐观锁,新增 sqlite 持久化)→ **read-back(新增:解析 CLI 原生配置比对,检测漂移)** → selection(切换模型)→ **migrate(接线:版本升级)** → **archive/dematerialize(接线:恢复备份)** → 变更通知(subscribe 已有,补消费者)

## 三、分阶段实施

### 阶段 1:kernel 契约增强(sdkwork-kernel)
1. `sdkwork-agent-kernel/src/configuration.rs`:
   - 新增 `ProviderModelConfigurationStatus`(provider_scope、`materialization: NotMaterialized|Materialized|Diverged|Unsupported`、effective_base_url、effective_default_model、credential_configured、issues: Vec<String>)
   - `AgentConfigurationProvider` 新增 `read_model_configuration(&self, agent_id, profile_id) -> KernelResult<ProviderModelConfigurationStatus>`,默认返回 Unsupported(向后兼容)
2. `sdkwork-kernel-plugins/.../provider_config_file.rs`:公开 `read_provider_config_text` 辅助(基于现有 read_provider_config)
3. 8 个 provider 实现 `read_model_configuration`(解析自己写的原生配置):codex 复用 `current_is_sdkwork_materialized`(materializer.rs:44-69)重构;claude/mimo 解析 settings.json env;gemini 解析 .env;hermes 解析 config.yaml+`.env`;openclaw/opencode 解析 JSON;rig 返回 Unsupported
4. 测试:`sdkwork-agent-kernel/tests/` 新增 read-back 契约测试 + 各 provider 补 read-back 单测

### 阶段 2:sdkwork-agents 持久化 + 完整 HTTP 面
5. 新增 `SqliteAgentConfigurationStore`(实现 kernel `AgentConfigurationStore`):
   - 新表 `agent_model_configuration_profile`(profile_id PK、agent_id、engine_id、configuration_id、provider_scope、configuration_version、status、configuration JSON、secret_bindings JSON、created_at/updated_at、version 乐观锁),落 `database/ddl/baseline/postgres/` 新 baseline 迁移(0002)
   - 实现 subscribe 变更投递
6. `AgentModelConfigurationRuntime::with_providers`(http.rs:1271)注入 sqlite store 替换 InMemory
7. HTTP 新端点(app-api,同步更新 `specs/openapi/agents-app-api.openapi.yaml` + 重新生成 SDK):
   - `GET /app/v3/api/ai/model_configurations`(分页 list,按 engine 过滤)
   - `GET /app/v3/api/ai/model_configurations/{profileId}`(detail,api key 一律 redact)
   - `GET /app/v3/api/ai/model_configurations/{profileId}/status`(store 状态 + provider read-back 比对,漂移检测)
   - `POST /app/v3/api/ai/model_configurations/{profileId}/archive`(archive_profile → dematerialize_model_configuration,恢复 `.sdkwork.bak`)
   - `POST /app/v3/api/ai/model_configurations/migrate`(plan_configuration_upgrade → migrate_profile 接线)

### 阶段 3:sdkwork-models 客户端桥接
8. sdkwork-models 新增桥接协调器(放 `sdkwork-api-models-standalone-gateway` 或新 coordinator crate,HTTP-only 不引 agents 依赖):

   - api key 遵循既有边界:客户端 sqlite 明文 → apply 请求一次性传输,服务端经 SecretProvider 存 vault,不落 profile
